1. Resumen del proyecto
El proyecto propone desarrollar un chatbot para la atención de consultas frecuentes en Black Dog Store. Los clientes podrán comunicarse desde una interfaz web para consultar horarios, garantías, servicios y datos de productos. Las respuestas se obtendrán de una base de preguntas frecuentes y, cuando corresponda, de información consultada mediante una API autorizada. Los casos que requieran criterio humano podrán derivarse a un asesor.
Se aplicarán conceptos de computación en la nube mediante contenedores, microservicios, seguridad y servicios de Amazon Web Services (AWS). Durante la etapa inicial se implementará un bot basado en reglas y preguntas frecuentes; añadir inteligencia artificial generativa será una mejora futura, no una dependencia del entregable inicial.
1.1. Problema identificado
Una tienda de tecnología recibe consultas repetidas sobre características, disponibilidad, servicios técnicos y condiciones de compra. La atención exclusivamente manual puede producir demoras y dificultar la organización del historial de solicitudes.
1.2. Objetivo general
Diseñar y desarrollar un sistema web de atención automatizada para Black Dog Store, basado en microservicios y contenedores, incorporando controles de seguridad y recursos AWS para apoyar la gestión de accesos y archivos.
1.3. Objetivos específicos
Construir una interfaz web de chat, registro e inicio de sesión.
Implementar servicios independientes para conversaciones y consultas de información.
Crear y documentar endpoints REST, con respuestas HTTP controladas.
Gestionar usuarios, perfiles, permisos, preguntas frecuentes e historial.
Configurar AWS IAM y un bucket de Amazon S3 bajo permisos restringidos.
Realizar pruebas unitarias, de integración, seguridad y carga según cada entrega.

3.1. Reglas funcionales clave
El chatbot responderá con información verificable y autorizada; de no existir, indicará que se requiere confirmación.
El cliente podrá consultar únicamente sus conversaciones y recursos permitidos.
Las acciones de administración estarán restringidas a personal autorizado.
El componente de chat no dispondrá de acceso directo a credenciales ni datos privados de la tienda.
Las pruebas y datos ficticios se usarán antes de habilitar cualquier enlace con información real.

5.1. Flujo principal
Cliente → interfaz Next.js → API Django → servicio de chatbot → FAQ o catálogo autorizado → respuesta al cliente. Los mensajes y estados se guardan en PostgreSQL. Los archivos permitidos se administran en S3 mediante servicios con credenciales y permisos mínimos.
5.2. Separación por microservicios
Servicio de usuarios: registro, login, autorización y roles.
Servicio de chatbot: procesamiento de consultas, reglas y derivación.
Servicio de catálogo: adaptador de consulta a la fuente autorizada de productos.
Persistencia: base de datos académica y almacenamiento de archivos según el tipo de información.

8.1. Interpretación de las cifras de prueba
El material del docente menciona rangos aproximados de 50–100, 1,000–5,000 y 10,000–50,000, pero no define explícitamente si son usuarios concurrentes, peticiones acumuladas u otra variable. Antes de ejecutar las pruebas se debe acordar un escenario reproducible y reportarlo claramente, sin asumir que las cifras representan usuarios simultáneos.
8.2. Seguridad durante pruebas de carga
Las pruebas masivas se realizarán únicamente en un entorno controlado con autorización. Se debe evitar dirigir cargas de prueba a la web comercial en producción o provocar consumos no previstos en AWS.

El prototipo se considerará listo cuando sus módulos comprometidos funcionen en el entorno de evaluación, el equipo pueda demostrar roles, chat, preguntas frecuentes, persistencia, endpoints, seguridad, recursos AWS y los controles exigidos en la entrega correspondiente.
